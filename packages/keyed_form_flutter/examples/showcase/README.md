# showcase

One app, two `keyed_form_flutter` forms: **sign in**, and on a valid form,
push the **tour builder**. Both models / field references / validators are
generated by `keyed_form_gen` from a `ks.object` schema.

```bash
cd packages/keyed_form_flutter/examples/showcase
dart run build_runner build     # generate the *.kfg.dart
flutter create .                # once — adds the platform runners
flutter run -d chrome           # or macos / windows / linux / a device
```

## Layout

| File | What it is |
| --- | --- |
| [`lib/main.dart`](lib/main.dart) | the `MaterialApp` — `home:` is the login screen |
| [`lib/login/login_schema.dart`](lib/login/login_schema.dart) | `ks.object` → `LoginSchema` (email + password + remember) |
| [`lib/login/login_screen.dart`](lib/login/login_screen.dart) | the login form; a valid submit pushes `TourBuilderScreen` |
| [`lib/tour_builder/tour_schema.dart`](lib/tour_builder/tour_schema.dart) | `ks.object` → `TourSchema` — enum, bool, int min/max, nested list, two cross-field `.refine`s |
| [`lib/tour_builder/tour_builder_screen.dart`](lib/tour_builder/tour_builder_screen.dart) | the screen — controller lifecycle, the `KeyedFormMode` switch, Save / Reset / Simulate-server-error, and the two-phase scroll-to-first-error |
| [`lib/tour_builder/tour_form.dart`](lib/tour_builder/tour_form.dart) | the form itself — the `CustomScrollView` body and one card per stop |
| [`lib/tour_builder/state_inspector.dart`](lib/tour_builder/state_inspector.dart) | the "not the form" chrome — the `Unsaved` badge and the live state panel |

| `*.kfg.dart` | **generated** — committed, regenerate with `build_runner` |

## What the tour builder shows

- text, dropdown (enum), switch (bool), stepper (int) fields;
- a by-id list of stops — add / remove / reorder;
- a live **KeyedFormMode** switch (eye icon) — watch when errors surface;
- **Public tour** on with a short name → a cross-field error on the name;
- nights past 14 total → a list-level error on `stops`;
- **Simulate server error** → a `title` error merged from a fake JSON body;
- dirty tracking + **Reset**;
- a responsive master / detail layout with a live state inspector;
- add ~20 stops, scroll down, clear the name, **Save** → it jumps the
  (off-screen, unbuilt) name field back into view.

### Scroll-to-error with a lazy list

`KeyedFieldRegistry.revealFirst` can only scroll to a field whose
`KeyedFieldAnchor` is currently mounted. In a lazy scroller the erroring field
may not be built, so `_revealFirstError` in `tour_builder_screen.dart` is two
phases:

1. **coarse** — jump the *section* holding the error into range, reading each
   section sliver's `precedingScrollExtent` and nudging the viewport to force
   the lazy slivers between it to lay out;
2. **exact** — once the field has laid out and re-registered its anchor,
   `registry.revealFirst(keys, alignment: 0.5)` does the precise scroll.

The plan_tour app's `itinerary_builder_screen.dart` is the full-scale version
(per-day `SliverMainAxisGroup`s, pinned headers, deep-link jumps, a nav rail).
